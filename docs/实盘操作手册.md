## 0. 链路全景

本站有**两条互不相干的执行链路**。搞混它们是绝大多数困惑的根源。

```
【链路 A · 自建镜像】本站产生信号，本站下单
  量化引擎 ┐
  Webhook  ├─→ 信号执行器 emitSignal ─→ [跟单关系运行中 + API Key 已绑定] ─→ OKX 真实下单
  手动发布 ┘

【链路 B · OKX 原生跟单】OKX 产生信号，OKX 下单，本站只做登记
  OKX 官方带单员 ─→ 导入本站当信号源 ─→ first-copy-settings ─→ OKX 引擎实时同步开平仓
```

| | 链路 A（自建镜像） | 链路 B（OKX 原生跟单） |
|---|---|---|
| 信号从哪来 | 本站量化 / Webhook / 手动 | OKX 官方带单员 |
| 谁下单 | 本站（Worker 轮询 + 交易所 API） | **OKX 自己** |
| 轮询延迟 | 有（取决于 tick 频率） | 无 |
| 带单员隐藏持仓时 | ❌ 跟不了（不知道他买什么） | ✅ 照跟（OKX 不需要告诉本站） |
| 本站能否改参数 | 全部可控 | 金额/比例/止盈止损，改完同步给 OKX |
| 盈亏显示 | 本站结算 | 站内显示「以 OKX 为准」 |

**两条链路不会互相打架**：`lib/executor.ts` 里有硬护栏 —— OKX 源的信号不会被链路 A 执行
（`emitSignal` 直接抛错，筛选跟单关系时排除 `engine === "okx"`），避免同一笔仓位下两次。

**最容易误解的一点**：建好信号源**不等于**会下单。信号源只负责"产生信号"；
真正决定能否成交的是后面两个条件 —— 跟单关系、已绑定的 API Key。
看到 `dispatched: 0`（下发 0 笔）时，先查这两项，而不是怀疑信号源。

## 1. 前置：绑定交易所 API Key

路径：`/api-keys`

### 为什么优先用 OKX

| 交易所 | 在 Cloudflare Workers 上 |
|---|---|
| **OKX** | ✅ 可用（当前部署环境唯一生产可用的） |
| 币安 Binance | ❌ 出口 IP 被拒（403 / 451） |
| 其余 6 家 | 未接适配器 |

币安适配器代码是写好的，卡在宿主出口 IP。若必须用币安，需把执行层挪到非 Cloudflare 主机，控制台与调度留在 Worker（适配器零改动）。

### 绑定要点

- 需要三样：**API Key**、**Secret**、**Passphrase**（OKX 特有，币安没有）
- OKX 账户模式必须是「**单币种保证金**」或「**跨币种保证金**」，简单模式会下单失败
- Key 权限**只勾「交易」**。勾了「提现」会被系统直接拒收 —— 这是硬拦截，不是 bug
- 绑定时会当场做一次真实验签，通过才保存

> 想用 **OKX 原生跟单**（链路 B）时，这个 Key 需要勾上**「交易」**权限即可；
> OKX 的跟单接口走的是同一套交易权限，不需要额外开「跟单」开关。
> 但**必须填 Passphrase** —— 跟单接口的签名同样要它，漏填会在 `first-copy-settings` 上报
> `50113 Invalid Passphrase`。

密钥以 AES-256-GCM 加密存储（主密钥 `COINCE_SECRET_KEY`），任何接口都不会下发明文。

### 2.1 OKX 官方带单员（推荐起点）

路径：`/sources` → 右上「**从 OKX 导入带单员**」

这是**不需要你自己发明策略**就能开始的方式：直接把 OKX 跟单平台上真实存在的带单员
拉进来当信号源。页面上每一个数字（AUM、跟单人数、累计收益、胜率、带单天数、收益曲线、
头像）都来自 OKX 公开接口，**本站不做任何估算或编造**。

**品类：合约跟单 / 现货跟单**

OKX 的带单员分两册，实测全集为 **合约（SWAP）253 个**、**现货（SPOT）159 个**。
弹窗左上角切换，两册互相独立。注意 **同一个 `uniqueCode` 可能同时出现在两册里，
但那是两个不同的带单产品**（AUM、收益、品种、跟单人数都不同），
所以本站的唯一键是「品类 + uniqueCode」，不会互相覆盖。

**一次把整册拉进来**

点右上「**全部导入（合约 / 现货）**」会把当前品类下的所有带单员同步进本地。
因为 OKX 排行榜一页只给 20 条，这件事必须分批做（合约约 13 批、现货约 8 批），
界面上有进度条，中途可以「停止」——已经写完的批次保留。
想更新业绩再点一次即可：幂等，只更新不重复。

> 全量导入**不做**持仓隐藏探测。原因是 253 人 × 每人一次子请求会超出
> Cloudflare Workers 的单请求子请求上限。所以全量进来的带单员不显示「持仓隐藏」标记，
> 这不影响 OKX 原生跟单。要知道某个人是否隐藏持仓，单独点他那行的「导入 / 刷新」即可。

**导入弹窗里的操作**

| 控件 | 说明 |
|---|---|
| 品类 | 合约跟单 / 现货跟单，两册独立 |
| 排序 | 综合 / 收益率 / 累计盈亏 / 管理资金 / 胜率 / 跟单者收益 |
| 带单时长 | 不限 / ≥7 / ≥30 / ≥90 / ≥180 天（OKX 的枚举选择器） |
| 最低管理资金 | 单位 USDT，留空不限 |
| 全部导入 | 把当前品类的整册同步进来（分批 + 进度 + 可中断） |
| 导入 / 刷新 | 单个导入；已导入的显示「刷新」，只覆盖业绩数据，保留你本地的启用状态与备注 |

导入后回到 `/sources`，列表支持按名称 / `uniqueCode` / 交易对搜索，
以及按来源、品类筛选和按管理资金 / 累计收益 / 带单天数排序（300+ 条必须靠这些找）。

底部会实时显示 OKX 当前的跟单限额（单笔上下限、总额上限、比例上限、止盈止损上限），
这些也是从平台现取的，提交前会在前端校验。

**字段口径**（容易看错的地方）

- OKX 的 `pnlRatio`（收益率）、`winRatio`（胜率）都是**小数**，本站展示时 ×100 变成百分比
- OKX 的 `pnlRatio` **不等于** `pnl / aum`，不要拿两个数去互相验算
- 「跟单人数」是**在 OKX 上**有多少人跟了他，不是本站的跟单者数量

**持仓隐藏**

部分带单员的当前持仓是隐藏的（OKX 返回的 `instId` 为空），列表上会打「持仓隐藏」标记。
这只影响链路 A（自建镜像跟不了，因为不知道他买什么），**不影响链路 B** ——
OKX 原生跟单由 OKX 引擎同步他的成交，本站不需要知道。所以看到这个标记不用慌。

**导入失败的常见原因**

`uniqueCode` 失效（带单员已停止带单），或该 code 排名在扫描范围之外。
导入结果会逐条列出成功/失败与原因，不会静默跳过。

> **实现备忘（踩过的坑）**：OKX 的 `public-lead-traders` 接口 **`limit` 上限是 20**，
> 传 21 就被 400 拒绝（跟 OKX 其它接口惯用的 100 不一样）。曾经在这里写 100，
> 结果整条导入链路返回**空的 502**（没有堆栈、没有错误信息，很难查）。
> 现在上限夹紧在 `lib/okx-copy.ts` 的 `RANK_MAX_LIMIT`，调用方传什么都不可能再发给 OKX。
>
> `instType` 只接受 `SWAP` / `SPOT`，传 `MARGIN` / `FUTURES` / `OPTION` 一律 400。
> 翻页要带上首页返回的 `dataVer`，否则榜单刷新会让数据漂移。
> 按单个 `uniqueCode` 导入时靠翻页反查（最多扫 13 页 = 253 名，正好覆盖合约全集），
> 所以榜上的任何人都能导入；反查不到基本只剩一种原因：他已经停止带单了。

### 2.2 内置量化引擎

额外字段：策略类型、K 线周期（1m/5m/15m/1h/4h/1d）、策略参数（JSON）。

| 策略 | 默认参数 | 触发逻辑 |
|---|---|---|
| `ema_cross` EMA 均线交叉 | `{"fast":12,"slow":26}` | 快线上穿慢线开多、下穿开空；反向持仓先平 |
| `rsi_revert` RSI 均值回归 | `{"period":14,"low":30,"high":70,"exit":50}` | 跌破 low 开多、突破 high 开空；回到 exit 平仓 |
| `breakout` 区间突破 | `{"lookback":20}` | 收盘价破前 lookback 根的高/低点，顺势开仓 |
| `grid` 网格 | `{"gridPct":1.5}` | 相对基准下移 gridPct% 买入；上移则平仓并上移基准 |

**运行方式**

- 页面「立即运行一轮」= 跑全部量化源；单条「跑一轮」= 只跑该条
- 线上由 GitHub Actions 每 5 分钟自动跑（`.github/workflows/tick.yml`）
- 结果面板显示每个源的下发 / 成功 / 失败数

**同一根 K 线只判定一次**（`engineState.lastBarTs` 去重）。
15m 策略最快 15 分钟出一次信号，连点「跑一轮」不会多出信号 —— 这是防重复下单的保护。

> ⚠️ 这四个策略是**规则示例**，不是经过验证的盈利系统。参数需自行回测调整。

### 2.2 外部 Webhook

创建后列表条目下方出现带 token 的独享地址：

```
https://copytrade.138148178.xyz/api/webhook/signal?token=<32位随机串>
```

POST body：

```json
{
  "symbol": "BTC/USDT",
  "side": "LONG",
  "action": "OPEN",
  "price": 68000,
  "leverage": 5,
  "note": "TradingView 预警：EMA 金叉"
}
```

**宽松归一化**（无需严格对齐）

| 字段 | 接受写法 |
|---|---|
| `side` | `LONG`/`SHORT`、`buy`/`sell`、`b`/`s`、`多`/`空`、`开多`/`开空` |
| `action` | `OPEN`/`CLOSE`/`ADD`/`REDUCE`、`exit`、`increase`；默认 `OPEN` |
| `symbol` | `BTC/USDT`、`BTCUSDT`、`BTCUSDT.P`、`BTC-USDT-SWAP`、`ETHUSDT_PERP`、`BINANCE:BTCUSDT` 均归一为 `BTC/USDT` |
| `price` | 省略则取最新价 |

**先用 GET 验地址**（不会下单）：

```
https://copytrade.138148178.xyz/api/webhook/signal?token=<token>
```

返回信号源名称、状态与用法说明，确认通了再接触发端。

**curl 实测**

```bash
curl -X POST "https://copytrade.138148178.xyz/api/webhook/signal?token=<TOKEN>" \
  -H "content-type: application/json" \
  -d '{"symbol":"BTC/USDT","side":"LONG","action":"OPEN"}'
```

返回含 `dispatched` / `succeeded` / `failed`。

**状态码**

| 码 | 含义 |
|---|---|
| 401 | 缺少或无效 token |
| 409 | 该信号源已暂停（status ≠ live），信号未执行 |
| 400 | 缺 symbol，或 side 无法识别 |

token 泄露 → 列表里点「轮换 token」，旧地址立即失效。

### 2.2.1 TradingView 预警接入

**第一步：TradingView 里创建预警**

在图表上打开要跟的品种 → 右键 → 添加预警（或按 `Alt+A`）。

**第二步：填 Webhook URL**

预警弹窗 → Notifications 标签 → 勾选 **Webhook URL** → 粘贴：

```
https://copytrade.138148178.xyz/api/webhook/signal?token=<你的token>
```

> TradingView 免费版**不含 webhook 功能**，需要 Essential 及以上套餐。发出请求的服务器来自 TradingView 侧，与本站在 Cloudflare 上的出网限制无关。

**第三步：填 Message**

Message 里贴 JSON。两种写法：

*写法 A — 固定符号（推荐，最不容易出错）*

```json
{"symbol":"BTC/USDT","side":"buy","action":"OPEN","note":"TradingView 预警"}
```

不管图表切换成什么品种，都固定下单到 BTC/USDT。想跟多个品种就建多个预警/多个信号源。

*写法 B — 用变量（适合 Pine 策略，一个预警跟全部品种）*

```json
{"symbol":"{{ticker}}","side":"{{strategy.order.action}}","action":"OPEN","note":"{{strategy.order.comment}}"}
```

| 变量 | 取值 | 本站是否认 |
|---|---|---|
| `{{ticker}}` | 现货 `BTCUSDT`；**永续 `BTCUSDT.P`** | ✅ 两种都认 |
| `{{strategy.order.action}}` | `buy` / `sell` | ✅ 认 |
| `{{strategy.order.contracts}}` | 张数 | 未使用（本站按跟单关系的资金比例算仓，忽略此字段） |
| `{{strategy.order.comment}}` | 策略里填的备注 | ✅ 作为 `note` |

> ⚠️ `{{strategy.*}}` 系列变量**只在 Pine 策略（strategy）的预警里可用**。
> 普通指标（indicator）预警里没有成交动作，必须用写法 A 手写 `side`。
> 用错会发出字面量 `{{strategy.order.action}}`，服务端识别不了 side 会返回 400。

**平仓**：另建一个预警，`"action":"CLOSE"`。本站 `emitSignal` 收到 CLOSE 会去平掉该品种的对应持仓。

**排障顺序**

1. 先用 `git bash` / Postman 直接 POST 一次，确认服务端没问题（返回 code 200 且 `ok:true`）
2. 再看 TradingView 预警日志（Alert log），确认它真的发了请求、返回码是多少
3. 若返回 403/401 → token 错或被轮换过
4. 若返回 400 且提示 side 无法识别 → 用了 `{{strategy.*}}` 但预警不是策略型，或变量名拼错
5. 若 `ok:true` 但 `dispatched:0` → 服务端收到了，但没人跟这个源，去 `/copy-trading` 建关系

## 3. 建立跟单关系

路径：`/copy-trading` → 交易员广场 → 选一个信号源 → 「开始跟单」

弹窗会**按信号源类型自动切换表单**，因为两条链路的参数根本不同：

**信号源是 OKX 带单员（链路 B，原生跟单）**

| 参数 | 取值 | 说明 |
|---|---|---|
| 跟单方式 | 固定金额 / 按比例 | 对应 OKX 的 `fixed_amount` / `ratio_copy` |
| 跟单总额 | USDT | 这个带单员最多占用多少钱 |
| 单笔金额 或 跟单比例 | USDT / % | 按上面选的方式二选一 |
| 保证金模式 | 跟随带单员 / 全仓 / 逐仓 | `copy` / `cross` / `isolated` |
| 止盈 / 止损 | % | 换算成小数后作为 `tpRatio` / `slRatio` 提交 |
| 平仓方式 | 跟随带单员 / 市价平 / 手动平 | 停止跟单时已有持仓怎么处理 |

表单下方实时显示 OKX 平台的限额（按其品类实时取自平台），超出会在前端拦下，
不会把必然失败的请求打到 OKX。

> 品类（合约 / 现货）**不用你选**，跟着信号源走 —— 跟单请求会自动带上该带单员所属的品类。
> 现货带单员的参数项与合约一致。

提交后会调用 OKX 的 `first-copy-settings`，**在你的 OKX 账户里正式建立跟单关系**。
之后带单员的开平仓由 OKX 引擎实时同步 —— 本站不参与下单。

> 取消跟单会调用 `stop-copy-trading`。默认「已有持仓保留在你的账户里」，**不会自动平掉**，
> 需要你到 OKX 手动处理。

**信号源是量化 / Webhook / 手动（链路 A，自建镜像）**

选择：信号源 + 交易所账户（OKX）+ 资金或比例 + 杠杆。

**名义额公式**：`保证金 × 杠杆`，单笔超过 10 万 U 会被截断到 10 万并推送通知。

**「我的跟单」表格**：OKX 原生跟单的行会显示「OKX 原生」标记，盈亏列显示「以 OKX 为准」
（本地不做结算，也不编一个 0 出来），并注明「开平仓由 OKX 引擎同步」。

## 4. 第一次试跑

按这个顺序，风险最小：

1. `/api-keys` 绑定 OKX（无提现权限的 Key）
2. `/sources` 新建一个**手动发布**型信号源，交易对选 BTC/USDT
3. `/copy-trading` 跟这个源，资金给最小（~10 U），杠杆 1
4. 回 `/sources` 对该条点「发信号」→ 开仓 → **勾上"只下给我自己"**
5. 检查结果
   - 返回 `成功 1 / 失败 0`
   - OKX 里出现真实持仓
   - `/trades` 与通知中心有记录

跑通之后再换量化源或接 Webhook。**不要**一上来就挂量化引擎 + 高杠杆。

### 走 OKX 原生跟单的最短路径

1. `/api-keys` 绑定 OKX（Key + Secret + **Passphrase**，只要「交易」权限）
2. `/sources` → 「从 OKX 导入带单员」。两种挑法：
   - **只挑几个**：按「带单时长 ≥90 天」筛一下，挑 AUM 和带单天数都过得去的逐个导入
   - **全都要**：点「全部导入（合约）」，把 OKX 上 253 个合约带单员整册同步进来，
     然后回列表用「按管理资金」排序，好的自然排在前面
3. `/copy-trading` → 筛选品类「合约」→ 找到这个带单员 → 开始跟单 → 方式选**固定金额**、
   总额给 **100 USDT**、单笔 **10 USDT**、保证金模式「跟随带单员」、先**不设**止盈止损
4. 去 OKX 网页/App 确认跟单关系已建立（跟单 → 我的跟单）
5. 等带单员开一笔，看 OKX 里是否同步建仓。本站不参与，所以本站的「我的跟单」只显示
   「以 OKX 为准」——**去 OKX 看真实盈亏**，不要在本站找数字

确认没问题后再逐步加总额、加带单员。

## 5. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `dispatched: 0` | 没有运行中的跟单关系 | 去 `/copy-trading` 建关系 |
| 执行失败、报凭据问题 | 未绑 API Key 或已失效 | 去 `/api-keys` 重新绑定 |
| Webhook 返回 409 | 信号源被暂停 | 列表里点「启用」 |
| 「跑一轮」不出信号 | 指标未触发，或该 K 线已判定过 | 正常现象，非故障 |
| 币安绑定后无法下单 | Worker 出口被拒 | 改用 OKX，或迁移执行层 |
| 删除信号源后跟单还在 | 删除不清理已有关系 | 手动去 `/copy-trading` 停掉 |
| 「从 OKX 导入带单员」报错 | 未登录站主，或 OKX 接口临时不可达 | 用站主账号；看 `/api/diag` 的 OKX 项 |
| 导入返回**空白的 502** | 多为参数越界（如 `limit` 超过 OKX 上限） | 已修（`RANK_MAX_LIMIT`）；若再现，先看响应正文里的 `OKX HTTP xxx · ...` |
| 导入时提示「在排行榜前 N 名中未找到」 | 该 `uniqueCode` 已停止带单 | 换个带单员 |
| 合约和现货里有**同名**带单员 | `uniqueCode` 在两册里重复，但是两个不同的带单产品 | 正常。用品类筛选区分，跟单时品类自动跟随 |
| 点「全部导入」后列表一下子多出几百个 | 全量同步就是这样（合约 253 / 现货 159） | 用搜索、来源/品类筛选、排序、分页收窄 |
| 「全部导入」中途停了 | 网络中断，或你点了「停止」 | 再点一次即可续上（幂等，不会产生重复） |
| 全量导入的带单员没有「持仓隐藏」标记 | 批量同步不逐个探测持仓（子请求上限） | 需要时单独点他那行的「刷新」 |
| 带单员显示「持仓隐藏」 | 他隐藏了当前持仓 | 不影响原生跟单；但自建镜像跟不了，别给他建链路 A 的关系 |
| OKX 跟单报 `50113 Invalid Passphrase` | 绑 Key 时 Passphrase 填错或漏填 | 去 `/api-keys` 重新绑定 |
| OKX 跟单报金额相关错误 | 超出平台限额（单笔 10 ~ 10 万 U） | 按弹窗里显示的实时限额调整 |
| 跟单表里 OKX 行盈亏显示「以 OKX 为准」 | 设计如此，本站不结算原生跟单 | 去 OKX 看真实盈亏 |
| 同一个带单员被下了两次单 | 理论上不会 —— 有护栏 | 若真出现，记下 `uniqueCode` 与时间反馈 |

## 6. 运维速查

- 备份线上 KV
```
npm run cf:backup
```

- 清空业务数据（保留站主账号与会话）
```
POST /api/admin/purge
```

- 删除信号记录（仅站主，用于清理联调痕迹；不碰成交记录与跟单关系）
```
DELETE /api/signals?id=sg_xxx        删单条
DELETE /api/signals?traderId=tr_xxx  删某信号源的全部信号
DELETE /api/signals?all=1            清空全部信号
```

- 出网连通性探针（需站主权限）
```
GET /api/diag
```
（含 OKX 跟单·带单员排行、OKX 跟单·带单员持仓两项，判断 OKX 是否可达就看这两条）

- OKX 跟单相关接口速查
```
GET  /api/okx/traders?limit=20&page=1&sortType=pnl_ratio&minLeadDays=2   浏览带单员（站主）
POST /api/okx/traders  {"uniqueCodes":["ABC123"]}                        导入/刷新（站主）
GET  /api/okx/config                                                     平台跟单限额
GET  /api/copy-trading?okxPositions=1                                    拉自己的真实跟单持仓
```
