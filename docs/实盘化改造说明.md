# 实盘化改造说明

> 从「演示复刻」切换到「真实交易」，本文说明**改了什么、为什么这样改、怎么用**。

## 一、先回答那个问题：coince.io 的「交易员」是怎么来的？

把源站首页文案和教程页读完，结论比较明确 —— 它**不是**从币安/OKX 带单广场抓的，
也**不是**用户自由入驻的交易员市场。它的定位是：

| 维度 | 源站做法 | 原文依据 |
|---|---|---|
| 信号谁生产 | **平台自营**：签约的真人交易员 + 自研量化策略 | 「由**真人顶级交易员**为你操刀」「**量化策略**实时适应市场波动」 |
| 用户资金 | **非托管**，留在自己的交易所 | 「资金留在你自己的交易所钱包，我们只执行交易」 |
| 接入方式 | 用户自建 API Key，只勾「交易」权限 + IP 白名单 | 教程页全程只让勾「交易」，还要填 Passphrase |
| 商业模式 | 零分润、不排队（对标 CEX 跟单的 20% 抽成、200–500 名额上限） | 「利润 100% 归你」「不设跟单人数上限」 |

所以「跟单列表里的交易员」= **平台侧的信号源**。复刻版要能实盘，就必须自己提供信号，
而这只有三条路：内置量化引擎、外部 Webhook、后台手动发布。**三种都已实现。**

## 二、⚠️ 最重要的一条：Cloudflare 出网限制

部署完成后实测发现一个**会直接决定能不能用**的事实。`/api/diag` 探针结果：

| 目标 | 结果 |
|---|---|
| 币安 合约行情 `fapi.binance.com` | **403 ❌** |
| 币安 现货 `api.binance.com` | **451 Service unavailable from a restricted location ❌** |
| 币安 备用域名 `fapi1/fapi2/fapi3` | **403 ❌** |
| Bybit `api.bybit.com` | **403（CloudFront 地区封锁）❌** |
| **OKX `www.okx.com`** | **200 ✅** |
| **Gate `api.gateio.ws`** | **200 ✅** |

**结论：币安与 Bybit 无法从 Cloudflare Workers 出网。** 这不是代码问题 ——
签名实现是对的，是 Cloudflare 的出口 IP 被这两家拒绝了。影响范围：

- 币安/Bybit 的 API Key **无法验签、无法下单**
- 币安行情拿不到 → 已把行情主源改成 **OKX**，Gate 兜底

**怎么办，两条路：**

1. **改用 OKX**（推荐，当前部署立刻可用）。
   绑定 OKX 时记得填 Passphrase，并把账户模式设为「单币种保证金」或「跨币种保证金」
   （源站教程里也这么说）。
2. **必须用币安**：把**执行层**（`lib/exchanges/` + `lib/executor.ts`）挪到一台
   非 Cloudflare 的主机（VPS / Cloudflare 之外的容器），Worker 只做控制台与调度，
   通过内网或带鉴权的接口调用那台机器下单。适配器代码不用改。

界面上的表现：绑定币安时选择框会直接标红提示「当前部署环境下不可用」，
绑定失败的错误信息也会明确写出 403/451 的原因，不会让你以为是 Key 填错了。
随时可以打开 `/api/diag` 复查出网探测结果（需站主登录）。

12 条假通知、若干假发票/假 API Key。

清理分两层：

**代码层**（永久生效，不会再生成）

- `lib/auth.ts`：删掉 `cloneDemoData()`（新用户/管理员会复制一份演示数据）；管理员余额由 100000 改为 0

- `lib/stats.ts`：删掉写死的 `maxDrawdown=9.42`、`sharpe=1.94`，删掉用 `totalPnl*0.0832` 伪造的「今日盈亏」和正弦波拟合的净值曲线
- `lib/market.ts`：行情从**合成正弦波**换成币安公开行情接口；拿不到真实数据源的字段（链上大额转账、清算热力图）**返回空数组而不是编造**

**数据层**（一次性）

- 后台接口 `POST /api/admin/purge?confirm=PURGE` 同样可以做，且会保活站主会话

## 四、新增的实盘能力

### 1. API Key：绑定即真实校验

`lib/keys.ts` + `lib/exchanges/`

- 绑定时会**真的用你的 Key 向交易所签一次名**，拉取账户权益、可用余额、持仓、账户模式
- Secret / Passphrase / APIKey 本身全部用 **AES-256-GCM 加密**后入库（`lib/crypto.ts`），
  主密钥来自 Worker 密钥 `COINCE_SECRET_KEY`，明文不落盘、不下发前端
- 交易所若明确返回**可提现**，直接拒绝绑定（币安 `/fapi/v2/account` 的 `canWithdraw`）
- OKX 不提供权限查询接口，这一项无法自动校验，界面会明确提示你去后台自行确认

已打通实盘下单的交易所：**币安 USDT-M 永续、OKX 永续（SWAP）**。
其余 6 家在 UI 上标注「即将支持」，绑定时会明确报错而**不是假装成功**。

### 2. 信号源：三种产生方式

| 类型 | 怎么用 | 适合什么场景 |
|---|---|---|
| `quant` 内置量化引擎 | 后台配置策略类型/K线周期/参数，服务端定时拉真实 K 线算指标 | 自包含，不依赖外部 |
| `webhook` 外部 Webhook | 每个信号源有独享地址 `/api/webhook/signal?token=xxx` | TradingView 预警、你自研的程序、第三方信号 |
| `manual` 手动发布 | 后台填一笔（交易对/方向/动作/价格/杠杆） | 人肉判断、跟别人的公开仓位 |

内置策略（`lib/quant.ts`，均为规则示例，**参数需自行回测**）：
- `ema_cross` EMA 均线交叉（默认 12/26）
- `rsi_revert` RSI 均值回归（默认 14 / 30 / 70）
- `breakout` 区间突破（默认 20 根）
- `grid` 网格（默认 1.5%）

同一根 K 线只判定一次（`engineState.lastBarTs` 去重），避免定时任务抖动重复下单。

### 3. 执行引擎：真的下单

`lib/executor.ts`，链路：

```
信号产出 → 找出该信号源下所有 running 的跟单关系
        → 逐条解析用户可用的交易所凭据
        → 名义额 = 分配保证金 × 杠杆（比例模式则先乘比例）
        → 调交易所 REST 真实下单
        → 回写成交记录 / 跟单盈亏 / 通知
```

几条刻意的设计：

- **串行下发**，不并行。慢一点，但每一笔都有明确的成功/失败回执
- **单笔名义额硬上限 10 万 USDT**（`MAX_NOTIONAL_PER_ORDER`）。超出的截断并推送风控提醒，
  防止「跟单资金 100 万 × 20 倍杠杆」这类笔误直接打穿账户
- **一家失败不影响其他**。某个用户的 Key 失效，只标记这一条关系
- **止损止盈挂在交易所侧**：币安用 `closePosition=true` 的 `STOP_MARKET` / `TAKE_PROFIT_MARKET`，
  OKX 用 `order-algo` 的 `conditional` 单。这样**即使本服务挂掉，风控依然生效**
- 平仓时直接用持仓的基础币数量（`qtyBase`）精确对齐，避免取整留下残仓

## 五、上线新配置（必做）

```bash
# 1) 加密主密钥 —— 不配置会退化用 ADMIN_PASS 派生，改密码后旧密文全解不开
npx wrangler secret put COINCE_SECRET_KEY

# 2) 定时任务的鉴权令牌（配合 .github/workflows/tick.yml）
npx wrangler secret put TICK_TOKEN

# 3) 仓库 Secrets 里补上 WORKER_URL 与 TICK_TOKEN，让 Actions 能定时驱动引擎
```

`TICK_TOKEN` 可以这样生成：

```bash
node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"
```

## 六、定时驱动量化引擎

`.github/workflows/tick.yml` 每 5 分钟 `POST /api/quant/run`。

为什么放 GitHub Actions 而不是 Workers Cron Trigger：OpenNext 打包出的 `worker.js`
入口是自动生成的，挂自定义 `scheduled` handler 需要侵入构建链路；Actions 本来就在用，
`curl` 一下最省事，也不占 Cloudflare 的 CPU 额度。

没有配置 `WORKER_URL` / `TICK_TOKEN` 时，这个 workflow 会直接跳过（不会报错刷屏）。

## 七、操作流程速查

**第一次用**
1. `/api-keys` → 绑定币安或 OKX 的 API Key（只勾「读取 + 交易」，配 IP 白名单）
2. `/sources` → 新建信号源（建议先建一个 `ema_cross` 的量化源，BTC/USDT，15m）
3. `/copy-trading` → 选中它 → 填**小额**保证金 + 杠杆 → 确认跟单
4. `/sources` → 点「立即运行一轮」验证链路（不一定会发信号，指标没交叉就不该发）
5. 想立刻验证下单链路，用 `/sources` 里对应信号源的「发信号」按钮手动发一笔，
   勾上「只下给我自己」

**日常**
- 看 `/notifications` 确认每笔是否成交，失败原因会写在这里
- 看 `/dashboard`、`/data-board` 的真实盈亏与净值曲线

## 八、已知局限（务必知道）

1. **数据存在单个 KV 键上做整库覆盖写**（`db:v2`）。多人并发写会丢数据。
   自用没问题；要多用户就换 D1，`lib/store.ts` 的接口不用改。
2. **KV 最终一致**，跨边缘节点传播最长约 60 秒。刚写入后立刻刷新可能看到旧值。
3. **量化策略只是规则示例**，不是经过验证的盈利系统。参数要自己调、自己回测。
   系统只负责把策略判定忠实地变成真实订单，**不为收益背书**。
4. **OKX 的提现权限无法通过 API 校验**，务必在 OKX 后台确认创建 Key 时只勾了「交易」。
5. 首页仍有源站风格的营销文案与用户评价（复刻自 coince.io 的版式）。
   那些是产品展示素材，不是账户数据；如果要正式对外，建议替换掉。
6. 跟单是**真实资金操作**。第一次务必用最小可下单金额跑通全链路，
   在交易所 App 里亲眼确认订单出现过，再放大。
